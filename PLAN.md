# Бизнес ЧАТ — план продукта

Репозиторий: [Saw28rus/BissnesCHAT](https://github.com/Saw28rus/BissnesCHAT). Код ставится одной командой с GitHub. Переписка и кабинеты живут только на вашем сервере.

Документ фиксирует первую версию: кто с кем говорит, как закрыт доступ, как устроена живая переписка и как кабинет поднимается на новом сервере из короткой копии. Следующие функции добавляются модулями и не ломают эти правила.

Для работы нужен домен. PWA, микрофон и защищённая cookie живут только в HTTPS. Открытый в интернет адрес без домена и сертификата для этого приложения не подходит.

## 1. Продукт

Бизнес ЧАТ — PWA для переписки администратора с клиентами.

Администратор сам создаёт личный кабинет и передаёт логин с паролем. Самостоятельной регистрации нет. Восстановления пароля со стороны клиента нет: забытый пароль меняет администратор.

Клиент видит только диалог с администратором. Других клиентов, их имена и переписку он не видит и написать им не может.

В переписке есть текст, документы, голосовые, ответ на сообщение, правка и удаление своего сообщения. Звонков нет.

Интерфейс на русском языке, со светлой и тёмной темой, плавной лентой и локальным уведомлением, пока приложение открыто.

Сервер рассчитан на VPS 2 CPU / 4 ГБ RAM / 50 ГБ диск: один процесс API, PostgreSQL и Caddy.

## 2. Границы первой версии

Входит:

- один администратор и много клиентов;
- блокировка кабинета и смена пароля администратором;
- один диалог на клиента;
- текст, файлы, голосовые;
- счета ЮKassa в диалоге с клиентом;
- рассылка выбранным кабинетам;
- ответ, правка своего текста, удаление своего сообщения;
- WebSocket для новых сообщений, правок и удалений;
- светлая и тёмная тема в настройках кабинета;
- локальные уведомления браузера;
- еженедельная короткая резервная копия и восстановление из админки;
- обновление кабинета из настроек, если на GitHub есть новый коммит;
- перенос на новый сервер без ручного восстановления PostgreSQL.

Не входит:

- звонки и видео;
- регистрация клиента и маршрут самостоятельной регистрации;
- письмо или ссылка «забыли пароль»;
- переписка клиента с клиентом и групповые чаты;
- удалённый Web Push, когда приложение полностью закрыто;
- голосовые, документы и полная история в еженедельной копии.

Позже, отдельными модулями: несколько сотрудников в диалоге с клиентом, Web Push, полный архив диска, шаблоны ответов, статусы «прочитано».

## 3. Стек

### Сервер

| Часть | Выбор |
|---|---|
| API | Python 3.12, FastAPI, Uvicorn (один worker) |
| База | PostgreSQL 16 |
| Модели и миграции | SQLAlchemy 2, Alembic |
| Пароли | argon2id |
| Сессии | запись в PostgreSQL, cookie `__Host-session` |
| Файлы | каталог на диске вне статики, только через API |
| HTTPS и статика PWA | Caddy |
| Запуск | Docker Compose |

Один worker обязателен: подписки WebSocket живут в памяти процесса. Несколько worker без общей шины потеряют часть событий. Когда процессов станет больше, шина добавляется через PostgreSQL `LISTEN/NOTIFY`, протокол клиента остаётся тем же.

Наружу публикуются только порты 80 и 443. PostgreSQL и Uvicorn остаются во внутренней сети Compose и на хост не пробрасываются. Uvicorn принимает заголовок прокси только от Caddy.

Первый администратор создаётся из `.env` один раз, если роли `admin` в базе ещё нет. Следующие запуски пароль из `.env` не перезаписывают.

### Фронт

| Часть | Выбор |
|---|---|
| Интерфейс | React, TypeScript, Vite |
| PWA | vite-plugin-pwa, кэш только оболочки приложения |
| Экраны | React Router |
| Запросы | TanStack Query |
| Живая лента | WebSocket |
| Голос | MediaRecorder, файл уходит на API |

Node на VPS в постоянной работе не нужен. Сборка PWA выполняется при деплое, Caddy отдаёт готовые файлы.

## 4. Как это работает

```text
Браузер (PWA)
  |  HTTPS, домен
  v
Caddy :443
  |-- /            статика PWA
  |-- /api/*       FastAPI
  |-- /ws          WebSocket
  v
FastAPI (один процесс, порт наружу не открыт)
  |-- PostgreSQL   кабинеты, диалоги, сообщения, сессии, журнал
  |-- /data/uploads документы и голосовые
```

Клиент и администратор пользуются одним приложением. После входа сервер отдаёт роль: администратор попадает в админку, клиент — в свой единственный чат.

Отправка текста сразу рисуется в ленте и несёт клиентский ключ идемпотентности. Повтор того же ключа после обрыва сети не создаёт второе сообщение. Когда сервер сохранил запись, лента подменяет временную карточку настоящей.

После обрыва WebSocket клиент запрашивает синхронизацию по времени `updated_at`, а не по UUID: приходят и новые сообщения, и правки, и удаления, случившиеся пока связь лежала. Слияние идёт по UUID сообщения, поэтому дублей на экране нет.

## 5. Модель доступа

Роли: `admin` и `client`. Роль записывает только сервер. В запросах клиента поля роли нет.

Логин уникален без учёта регистра.

У каждого клиента ровно один диалог. Он создаётся вместе с кабинетом. В базе на это стоит ограничение уникальности.

Правила на каждом запросе и на каждом событии WebSocket:

- без сессии нет ни данных, ни сокета;
- рукопожатие WebSocket с чужим `Origin` отклоняется;
- клиент читает и пишет только свой диалог;
- чужой id даёт 404 без пояснения, существует ли объект;
- администратор видит все кабинеты и все диалоги;
- править и удалять сообщение может только автор;
- ответ ссылается только на сообщение того же диалога;
- цитату собирает сервер, текст цитаты от клиента не принимается;
- файл отдаётся только участнику своего диалога;
- выгрузку и загрузку резервной копии делает только администратор;
- маршрута самостоятельной регистрации нет.

Блокировка кабинета сразу гасит сессии и сокет. Заблокированный клиент видит экран «кабинет отключён» и не отправляет сообщения. Сама блокировка переписку и файлы не удаляет.

## 6. Безопасность

| Угроза | Мера |
|---|---|
| Подбор пароля | argon2id, тот же порядок проверки, если логина нет, лимит попыток по IP и логину, общая формулировка ошибки |
| Кража cookie | `HttpOnly`, `Secure`, `SameSite=Lax`, префикс `__Host-`, только HTTPS |
| Запрос с другого сайта | сессионная cookie недоступна скрипту; отдельная cookie CSRF `__Host-csrf` читается страницей и повторяется заголовком; для сокета проверяется `Origin` |
| Чужой диалог, файл или цитата | проверка участника, UUID вместо последовательных номеров, цитата только из того же диалога и только с сервера |
| Клиент назначает себе роль администратора | роль не принимается извне |
| Вредоносный файл | лимит размера, белый список типов, проверка сигнатуры, UUID на диске, каталог вне статики, выдача только через API, `nosniff`, документы как вложение, не как страница |
| Скрипт в тексте сообщения | хранение и отрисовка как текст, не как HTML |
| Утечка в логах | в логах нет паролей, тел сообщений, cookie и содержимого копий |
| Утечка через кэш PWA | service worker хранит только оболочку; ответы API, сообщения и файлы в Cache Storage не пишутся |
| Общий компьютер | сообщения не пишутся в localStorage; выход гасит текущую сессию на сервере |
| Чужая копия кабинетов | файл шифруется паролем администратора, пароль на сервере не хранится, расшифровка только в памяти |
| Подмена схемы прокси | Uvicorn доверяет заголовкам только Caddy, порты базы и API снаружи закрыты |
| Перехват по сети | только HTTPS и HSTS |

Заголовки: `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy` с микрофоном только для своего origin, запрет встраивания во фреймы.

Лимиты:

- текст сообщения — до 4 000 символов;
- документ — до 20 МБ, всегда `Content-Disposition: attachment`;
- фото сжимается на устройстве (длинная сторона до 1280 px, JPEG до ~1 МБ) и на сервере не больше 5 МБ;
- изображение в ленте — миниатюра, только если сигнатура и заголовок кадра совпали с JPEG, PNG или WebP; нажатие открывает файл;
- голосовое — до 8 МБ и до 3 минут, `Range` не обходит проверку сессии;
- типы документов: PDF, JPEG, PNG, WebP, DOC, DOCX, XLS, XLSX, TXT;
- голосовые: контейнер браузера (`webm` или `mp4`), без перекодирования;
- входящий кадр WebSocket — до 64 КБ, неизвестные события игнорируются;
- отправка сообщений и загрузка файлов ограничены по кабинету, чтобы один клиент не забил канал и диск;
- новая загрузка отклоняется, если на диске свободно меньше 5 ГБ;
- файл копии на восстановление — до 16 МБ.

Пароль кабинета — от 10 символов. Администратор задаёт его при создании и может заменить. Старый пароль не показывается: в базе лежит только хеш.

Смена своего пароля администратора требует текущий пароль. Смена пароля клиента текущего пароля клиента не требует. Смена пароля гасит все сессии этого кабинета. Выход гасит только текущую сессию. Отдельное действие в карточке клиента завершает все его сеансы без смены пароля.

Сессия живёт не дольше 14 дней и продлевается активностью. Вход выдаёт новую сессию.

Журнал хранит факт действия и UUID администратора, без текста переписки: кабинет создан, пароль сменён, блокировка, удаление, скачивание копии, восстановление.

Секреты (`SECRET_KEY`, пароль базы, пароль первого входа администратора) лежат в `.env`, не в репозитории и не в недельной копии.

## 7. Данные

Идентификаторы пользователей, диалогов и сообщений — UUID.

- `users` — логин, роль, хеш пароля, имя, статус (активен / заблокирован), дата создания;
- `user_settings` — тема (`light` или `dark`), локальные уведомления включены или нет;
- `sessions` — хеш идентификатора сессии, пользователь, срок, момент отзыва;
- `conversations` — один клиент, уникальная связь с кабинетом;
- `messages` — диалог, автор, тип (`text`, `file`, `voice`), текст, вложение, `reply_to_id`, цитата, клиентский ключ идемпотентности, время сервера, `edited_at`, `deleted_at`, `updated_at`;
- `message_revisions` — предыдущий текст, пока сообщение не удалено; в ленте не показывается и в копию не входит;
- `attachments` — исходное имя, тип, размер, путь, длительность голосового;
- `admin_audit` — действия администратора;
- `backup_meta` — время последнего скачивания; сам файл на сервере не хранится.

Ключ идемпотентности уникален в пределах диалога.

Время хранится в UTC и показывается в местном времени устройства. Время сообщения ставит сервер.

Удаление своего сообщения мягкое для ленты и жёсткое для содержимого: текст очищается, строки правок удаляются, файл с диска удаляется, фрагмент в чужих цитатах на это сообщение заменяется на «Сообщение удалено», в ленте остаётся та же пометка. После удаления старого текста нет ни в самом сообщении, ни в цитатах, ни в правках, ни в недельной копии. Править можно только свой текст. Файл и голосовое удаляются и отправляются заново, подмена байтов у того же сообщения не делается.

Удаление кабинета удаляет диалог, сообщения, правки и файлы этого клиента. Администратор подтверждает это отдельным шагом.

Индексы: сообщения по `(conversation_id, created_at, id)` и по `(conversation_id, updated_at)`, уникальность логина в нижнем регистре, сессии по хешу.

## 8. WebSocket

Адрес: `/ws`. Сокет поднимается после проверки сессии и `Origin`.

Клиент не выбирает подписку. Сервер сажает его в единственный его диалог. Администратор получает события всех диалогов: иначе список клиентов и локальное уведомление не узнают о новом письме, пока открыт другой чат. Чужим клиентам эти события не уходят.

События сервера:

- `message.created`
- `message.updated`
- `message.deleted`
- `client.updated` — только администратору

Текст, файл и голос сохраняются обычным запросом. Сокет разносит уже записанное сообщение и не перевозит сами файлы.

Обрыв: пауза перед повтором растёт до 15 секунд, затем синхронизация по `updated_at`. Повтор того же UUID не рисует вторую строку. Пока сокет жив, список диалогов не перезапрашивается на каждое письмо: строка превью берётся из события.

## 9. Ответ, правка, удаление

Клиент отправляет только `reply_to_id`. Сервер проверяет, что цель в том же диалоге, и сам записывает короткую цитату: автор и фрагмент текста либо подпись «Файл» или «Голосовое». Подделанная цитата из запроса не сохраняется.

Если исходное сообщение старше суток и в короткую копию не вошло, у ответа остаётся фрагмент цитаты. Если исходное сообщение удалили, этот фрагмент стирается. Если при восстановлении цели цитаты в файле нет, ссылка остаётся пустой, а уже сохранённый текст цитаты остаётся.

У своего сообщения в правом верхнем углу пузыря стоят значки ответа, правки и удаления. У чужого — только ответ. У фото значки над снимком, пузырь по ширине миниатюры. Это правило одно и для администратора, и для клиента: каждый меняет только то, что отправил сам. Правка помечается «изм.». Удаление открывает короткое подтверждение.

Второй участник видит правку и удаление сразу. Если в этот момент он был офлайн, то же изменение придёт синхронизацией при следующем входе.

## 10. Документы и голосовые

Загрузка идёт одним запросом с индикатором прогресса. Вложение принадлежит сообщению. Публичной ссылки нет.

Фото перед отправкой сжимается на устройстве. Сервер не доверяет типу из запроса: принимает JPEG, PNG и WebP только если совпали сигнатура и заголовок кадра, сторона не больше 8000 px. В ленте миниатюра, нажатие открывает файл.

Голосовое: зажал — запись, отпустил — отправил, смахнул влево — отмена. В ленте компактный плеер: слушать, дорожка, длительность — без системной полосы браузера. Запись при заблокированном экране не обещается.

Имя файла показывается человеку и очищается от путей. На диске хранится UUID.

## 11. Локальные уведомления

Уведомление показывает открытое приложение, когда по WebSocket приходит новое сообщение, а вкладка не в фокусе.

Включение спрашивается при входе и при открытии кабинета — не только в настройках. Браузер один раз показывает системный запрос. Без разрешения переписка работает как обычно. На iPhone запрос появляется после установки на экран «Домой»: из обычной вкладки Safari системные уведомления недоступны.

В тексте уведомления имя отправителя и тип: «сообщение», «файл» или «голосовое». Текст письма и имя файла в уведомление не входят, чтобы содержимое не светилось на экране блокировки.

Если систему или телефон выгрузили вкладку, сокета нет и уведомление не появится. На iPhone локальное уведомление из открытой вкладки ненадёжно даже у установленного PWA. Это граница первой версии, пока нет Web Push. Текущий переключатель Web Push не изображает.

## 12. Тема

Два значения: светлая и тёмная. Тёмная собрана отдельно, а не инверсией светлой.

Настройка хранится в кабинете и действует на всех устройствах после входа. Экран логина до входа берёт тему из локального значения, чтобы не мигать. После входа применяется тема кабинета. В localStorage больше ничего из переписки нет.

Переключение без перезагрузки. При системном «уменьшить движение» лента не анимируется.

## 13. Интерфейс

Это рабочий инструмент переписки, а не витрина. Сообщения администратора слева, сообщения клиента справа. Поле, файл и отправка парят у нижнего края одной полосой: файл слева, текст и запись голоса внутри поля, отправка справа. При открытии диалога лента сразу у последнего пузыря. При прокрутке лента уходит под поле; у последнего пузыря остаётся небольшой зазор, он не прячется под вводом. Своя отправка сразу показывает этот пузырь, даже если смотрели историю. После отправки текста и при записи голоса из поля клавиатура остаётся открытой. Голосовое: зажал — запись, отпустил — отправил, влево — отмена. У пузыря видны время и пометка «изм.». Над полем при ответе стоит цитата, её можно снять.

Шрифт интерфейса — Golos Text. Он сразу поддерживает кириллицу. Время в ленте набирается табличными цифрами. Inter, Roboto, Arial, Geist, Plus Jakarta Sans, Space Grotesk и «просто системный шрифт» не используются: это готовый вид, который повторяют шаблоны.

Светлая тема: чистая бумага `#f4f5f2`, чернила `#1c201e`, линии `#d4d9d5`, акцент спокойная зелень `#2c6e5d`. Тёмная: графит `#141716`, текст `#e8ebe8`, линии `#2c3230`, акцент мягкая зелень `#8fbfa8`. Цвет ошибки отдельно от акцента. Не охра-предупреждение, не фиолетовый, не индиго и не бардовый, без градиентной заливки экрана.

Форма: рамка 1 px вместо тени-облака, скругление полей 2 px, скругление пузыря не больше 10 px. Полоса ввода в чате — одна капсула: файл слева внутри, голос или отправка справа. Плотная вёрстка, цели нажатия на телефоне не меньше 40 px, поле ввода выше системной полосы жестов. Фокус с клавиатуры виден.

В интерфейсе нет стеклянных карточек, размытых пятен на фоне, неонового свечения, героя с крупным заголовком, сетки из трёх преимуществ, эмодзи вместо иконок и стандартной темы фиолетовых кнопок. Экран входа — тот же деловой каркас, что и чат, а не карточка по центру градиента.

Клиент:

- сверху «Админ», «В сети» или «Не в сети», настройки шестерёнкой;
- лента с разделителями дней;
- внизу текст, файл, голосовое;
- в ленте счёт от администратора с кнопкой «Оплатить»;
- настройки: тема, уведомления, выход.

Администратор:

- внизу четыре раздела: Чаты, Клиенты, Деньги, Настройки;
- панель парит над нижним краем, скругление как у поля ввода, без острых углов, кнопка слегка сжимается при нажатии;
- на узком экране список диалогов и чат открываются по очереди, панель при открытом чате скрыта;
- на широком список слева, диалог справа;
- Чаты: вкладки Диалоги и Рассылка; пустые диалоги остаются, но стоят ниже;
- Клиенты: компактный список, карточка открывается по нажатию; в карточке по умолчанию ФИО и телефон, остальные параметры администратор добавляет сам; значения копируются одним нажатием;
- Деньги: шаблон письма счёта, выставление и списки Выставленные / Просроченные / Оплаченные / Удалённые;
- Настройки: тема, пароль, ЮKassa, копия, журнал, обновление с GitHub;
- напоминание о копии старше 7 дней — в настройках, не над списком чатов;
- в шапке открытого чата можно скопировать ЭДО, если такой параметр есть в карточке.

Короткая строка в списке есть только у администратора. Это не полная история, а одно поле последнего сообщения, чтобы было видно, кто ждёт ответа.

Состояния экрана: загрузка, пустой диалог, обрыв сети, отказ во входе, заблокированный кабинет, ошибка файла, пустой поиск, мало места на диске.

При открытии диалога в ленту приходит окно последних двух дней — не меньше 40 и не больше 80 сообщений. Более ранние порции по 50 подгружаются, когда прокрутка доходит до верха. Длинная история не держит в DOM все тысячи пузырей.

Оболочка ставится на экран «Домой». Имя приложения — «Бизнес ЧАТ». Если открыто во вкладке, видна кнопка «Установить»: на Android вызывается системный диалог установки, на iPhone и iPad Safari не умеет поставить ярлык одной кнопкой — показывается как нажать «Поделиться» и «На экран „Домой“». У установленного приложения кнопки нет.

## 14. Админка

- создать кабинет: имя, логин, пароль, телефон, свои параметры (ЭДО, ИНН и любые другие), заметка для себя (клиент заметку не видит);
- изменить имя, логин, телефон, параметры и заметку;
- задать новый пароль клиенту и погасить его сессии;
- завершить сеансы клиента без смены пароля;
- заблокировать и снова открыть кабинет;
- удалить кабинет вместе с перепиской и файлами после отдельного подтверждения;
- открыть диалог и писать от своего имени;
- сменить свой пароль, назвав текущий;
- переключить свою тему и локальные уведомления;
- скачать недельную копию;
- восстановить копию с предпросмотром;
- видеть журнал действий;
- подключить ЮKassa номером магазина и секретным ключом;
- выставить счёт из раздела «Деньги» или из диалога: сумма, период, шаблон письма, срок;
- править шаблон письма счёта с полями имя, период, сумма, ссылка и срок;
- смотреть счета по статусам: выставленные, просроченные, оплаченные, удалённые;
- разослать одно сообщение выбранным кабинетам;
- обновить кабинет с GitHub из настроек, если есть новый коммит;
- видеть, сколько места занимают файлы и сколько диска свободно;
- видеть напоминание о копии в настройках, если её не скачивали больше 7 дней;
- видеть ход обновления с GitHub: что сейчас происходит и сколько примерно ждать.

Клиент не видит список людей, журнал, чужие диалоги и раздел копий.

## 15. Резервная копия и переезд

Недельная копия переносит кабинеты и, по выбору, текст за последние сутки. Это не архив переписки и не снимок диска.

### Что внутри

- версия формата и момент выгрузки;
- кабинеты клиентов: UUID, UUID диалога, логин, имя, телефон, свои параметры карточки, хеш пароля, статус, заметка, тема, флаг уведомлений;
- если переключатель включён: текстовые неудалённые сообщения за 24 часа до выгрузки, их UUID, время, автор, цитата ответа.

Автор в файле — признак «администратор» или UUID клиента, не внутренний счётчик базы. Реплики администратора на новом сервере встают на администратора этого сервера.

Переключатель «текстовые сообщения за последние сутки» по умолчанию включён. Если его снять, в файле только кабинеты и настройки.

Окно суток считается от нажатия «Скачать».

### Чего в файле нет

- голосовых, документов, путей и байтов файлов;
- сообщений старше 24 часов и любых нетекстовых сообщений;
- удалённых сообщений и таблицы правок, чтобы стёртый или старый текст не вернулся;
- сессий, журнала, секретов `.env`, пароля шифрования, ключа ЮKassa;
- хеша пароля администратора.

В копию попадает текущий текст сообщения, без предыдущих редакций.

### Шифрование

Администратор задаёт пароль файла от 12 символов. Ключ выводится через argon2id с умеренным объёмом памяти, чтобы выгрузка не забрала оперативку VPS, далее AES-256-GCM. Пароль на сервере не хранится и не восстанавливается. Сервер отдаёт файл ответом и вторую копию у себя не оставляет.

### Восстановление

1. Администратор загружает файл и вводит пароль шифрования.
2. Сервер расшифровывает его в памяти процесса, не на диск. Черновик привязан к сессии администратора и живёт не дольше 10 минут.
3. Предпросмотр показывает число кабинетов, число текстовых сообщений и момент выгрузки. Паролей и текста писем в предпросмотре нет. Если UUID уже есть на этом сервере, предпросмотр прямо говорит: пароль и настройки этого кабинета будут заменены данными из файла.
4. Подтверждение записывает всё одной транзакцией. Черновик после этого стирается из памяти.
5. Кабинет с тем же UUID обновляется, включая хеш пароля. Логин, занятый другим UUID, не затирается: строка пропускается.
6. Сообщения пропущенного кабинета не импортируются. Остальные текстовые сообщения вставляются по UUID. Повтор того же файла дублей не создаёт.
7. Если цель ответа в файл не вошла, остаётся только цитата.
8. Вложения не создаются. Сообщений, которых нет в файле, восстановление не удаляет и не добавляет.
9. Отчёт: создано, обновлено, пропущено и причина.

### Переезд на новый сервер

С GitHub копируется одна команда, на сервере установщик спросит только домен:

```bash
curl -fsSL https://raw.githubusercontent.com/Saw28rus/BissnesCHAT/main/deploy/get.sh | bash
```

Дальше:

1. Войти в админку паролем администратора из вывода установщика (он же в `deploy/.env`).
2. Загрузить последнюю недельную копию.
3. Клиенты входят прежними логинами и паролями. Тема и флаг уведомлений на месте.
4. Из переписки есть только неудалённый текст за сутки до снятия копии. Документы, голосовые и более старые сообщения с погибшего диска не возвращаются.

Пароль администратора на новом сервере — из нового `.env`. Сессии старого сервера недействительны. Секреты переносятся отдельно от недельного файла либо задаются заново.

Полный снимок томов Docker с голосовыми и всей историей в эту процедуру не входит и с недельной копией не смешивается.

### Обновление с GitHub

В настройках админки кабинет спрашивает GitHub, есть ли новый коммит на `main`. Если есть — кнопка «Обновить»: на весь экран выходит ход обновления (что сейчас происходит и сколько примерно ждать), сервер скачивает код и пересобирает контейнеры. Переписка и база не трогаются.

Та же команда установки с GitHub делает то же самое.

## 16. Скорость

- при открытии лента отдаёт последние два дня, не меньше 40 и не больше 80 сообщений; дальше порции по 50 курсором `(created_at, id)`;
- синхронизация после обрыва идёт по `updated_at` и сливается по UUID;
- отправка текста видна сразу и защищена ключом идемпотентности;
- список клиентов отдаёт карточку и одну строку последнего сообщения, не тела диалогов;
- длинная лента держит в DOM окно вокруг экрана;
- пул PostgreSQL ограничен под 4 ГБ;
- статика с хешем в имени кэшируется надолго, `index.html` — нет;
- голосовые не перекодируются;
- ориентир на этом VPS: порция ленты быстрее 300 мс при обычной нагрузке, событие WebSocket внутри сервера быстрее 100 мс. Сеть телефона клиента в эту цифру не входит.

Кэш сессии — оперативная память TanStack Query, не диск и не Cache Storage:

- оболочка PWA кэширует только статику с хешем; ответы API, сообщения и файлы туда не пишутся;
- переписка не пишется в localStorage;
- пока сокет жив, новая строка, правка и карточка клиента правят кэш по UUID, без повторного GET списка и без повторной первой порции ленты;
- поиск по кабинетам фильтрует уже полученный список; сервер остаётся источником самого списка;
- повторное открытие того же диалога в сессии сразу показывает окно последних дней, не накопленную за сессию историю; сервер подтверждает это окно;
- после обрыва сокета: синхронизация открытых лент по `updated_at` и один повтор списка кабинетов; сервер всегда прав, оптимистичная отправка заменяется ответом или событием с тем же UUID;
- выход и 401 очищают кэш сессии.

Одновременно онлайн ожидаются единицы и десятки человек. Загрузка останавливается, если свободно меньше 5 ГБ.

## 17. Расширяемость

- вид сообщения — поле типа, не новая несовместимая таблица на каждую функцию;
- тема и уведомления — отдельные колонки; следующий простой флаг добавляется миграцией;
- у файла копии есть номер версии, старый файл читается явным преобразованием;
- у события WebSocket есть имя и версия конверта;
- роль уже в модели, поэтому второй сотрудник позже добавляется правилами доступа.

Новая возможность — это новый каталог модуля, а не дописка в общий файл. Модуль не читает чужой диалог в обход раздела 5.

## 18. Структура репозитория

Код живёт в каталогах по зонам ответственности. Файл в корне репозитория или в корне `server/` и `web/src/` без своей папки не создаётся, кроме точек входа, которые перечислены ниже. Точка входа только собирает приложение: она не содержит правил доступа, вёрстки экранов и SQL.

Один файл — одна роль. Модель, схема запроса, сценарий и маршрут не складываются в один модуль на сотни строк. Если сценарий разрастается, он делится внутри своего каталога, а не переносится россыпью наверх.

В каждом модуле сервера свои файлы: `router.py`, `schemas.py`, `service.py`, `models.py`. Общих `models.py`, `routes.py` и `schemas.py` на всё приложение нет.

Во фронте у каждой фичи свой каталог: экран, части экрана, запросы и локальные стили лежат там. Общие стили — только токены, темы и сброс в `shared/styles/`. Одного `App.css` на весь интерфейс нет. Каталога `src/components/` россыпью нет: кнопка и поле, если они правда общие, лежат в `shared/ui/` по одному каталогу на элемент.

## 19. Порядок сборки

1. Каркас: домен, Caddy, закрытые порты базы и API, пустое PWA, миграции, первый администратор только если его ещё нет.
2. Вход, сессия, CSRF, `Origin` у WebSocket, заголовки, лимит попыток, выход.
3. Админка кабинетов: создание, правка, пароль, блокировка, сеансы, удаление, журнал.
4. Текст, порции ленты, идемпотентность, WebSocket, синхронизация по `updated_at`.
5. Ответ с серверной цитатой, правка, удаление содержимого, живое обновление второго участника.
6. Документы и голосовые, лимиты, диск, выдача только участнику, перемотка.
7. Тема и локальные уведомления.
8. Недельная копия: шифрование, черновик только в памяти, предпросмотр, восстановление, чистый сервер.
9. Плотность интерфейса, состояния ошибок, напоминание о копии старше 7 дней, свободное место.

Каждый шаг сдаётся вместе с проверкой доступа: клиент не читает чужое, заблокированный не пишет, копию получает только администратор.

## 20. Приёмка

- маршрута регистрации нет, клиент входит только выданным логином и не видит других клиентов;
- два логина, отличающиеся только регистром, не создаются;
- смена пароля клиента гасит его старый пароль и все его сессии;
- смена пароля администратора без текущего пароля не проходит;
- повторный запуск контейнеров не меняет уже созданный пароль администратора;
- повторная отправка того же клиентского ключа не создаёт второе сообщение;
- правка и удаление, сделанные пока второй участник был офлайн, появляются у него после входа;
- чужое сообщение нельзя ни изменить, ни удалить;
- удаление стирает текст, файл, старые правки и фрагмент этого сообщения в цитатах;
- цитату нельзя подменить текстом из запроса, ответ в чужой диалог не принимается;
- файл без сессии не открывается, в том числе запросом `Range`; клиент не скачивает файл чужого диалога;
- в кэше PWA нет тел сообщений;
- тема кабинета переживает повторный вход;
- локальное уведомление есть у свёрнутой живой вкладки на рабочем столе и Android и не обещается при закрытом приложении и как надёжное на iPhone;
- в уведомлении нет текста письма;
- недельный файл не содержит голосовых, документов, удалённых сообщений, старых редакций и сообщений старше суток;
- без пароля шифрования файл не читается, расшифрованный черновик на диск не пишется;
- на чистой установке возвращаются кабинеты, настройки и сохранённый текст суток;
- повторное восстановление не дублирует кабинеты и сообщения;
- логин из копии не перезаписывает чужой UUID, а предпросмотр предупреждает, если пароль существующего UUID будет заменён;
- порты PostgreSQL и API с хоста снаружи не принимаются;
- клиент не видит статус обновления и не может его запросить;
- сценарии лежат в каталогах модулей, а не в одной точке входа и не россыпью в корне;
- на экране нет типового шаблонного вида: фиолетовый градиент, стеклянные карточки, шрифты Inter, Geist и системная замена вместо Golos Text.

## 21. Осознанные ограничения

- гибель диска уничтожает документы, голосовые и историю, которая не попала в последнюю недельную копию;
- закрытое приложение не показывает уведомление, пока нет Web Push; на iPhone локальные уведомления этой версии ненадёжны;
- один процесс API, пока нет общей шины событий;
- голосовое записывается при открытом экране;
- пароль шифрования копии известен только администратору;
- восстановление на уже живой сервер заменяет пароли кабинетов с теми же UUID на пароли из файла; для погибшего сервера это и есть цель переноса.
